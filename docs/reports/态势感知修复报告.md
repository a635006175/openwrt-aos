# 态势感知「没数据」彻查与修复

日期：2026-11-07
实机：192.168.1.1（OpenWrt SNAPSHOT / kernel 6.18.55）
结论：**已修复并在实机验证通过**，自检 18/18 全过。

---

## 一句话结论

页面上"没有数据"不是采集不到，而是**三道独立故障叠加**：
① 统计时把几乎所有事件当"内网误报"丢掉了；② 防火墙规则里 `limit` 写在了 `drop` 前面，导致黑名单**形同虚设**且日志被压制；③ rpcd 缓存旧模块，**改完代码不重启就永远跑旧逻辑**。

第 ③ 条是"**修好了过一阵又没数据**"这个反复现象的真正机制。

---

## 根因（按影响排序）

### 根因 1【P0】统计过滤器把 100% 事件丢掉

`situational.uc` 的 `overview()` 里：

```js
if (ev.kind == 'threat' && (isPrivateIP(ev.src) || isPrivateIP(ev.dst))) continue;
```

本机 WAN 地址实测是 **`172.16.10.13/23`（私网，上级 NAT）**，而每次拦截**必然至少一侧是内网或本机**（`fwd_out` 是内网设备发起、`fwd_in` 目标是内网设备、`input` 的目标是私网 WAN 地址）。所以这条 `||` 判断把**全部事件**丢掉了。

实机量化（修复前后对比同一份数据库）：

```
24h 内事件总数        : 94
旧过滤器统计到的条数  : 0    <-- 页面当时显示的"24小时拦截"
新过滤器统计到的条数  : 94
被旧过滤器静默丢弃    : 94 条 (100.0%)
```

**单这一行就同时造成了全部 5 个症状**：24小时拦截=0、地区=0、威胁=0、地图空、时间线空、Top 来源空。

修复：只有**两侧都是私网**才算脏数据；单侧私网是正常的 `fwd_in`/`fwd_out`，必须保留。

### 根因 2【P0】`limit` 写在 `drop` 前面 —— 黑名单可被绕过

旧规则（单条）：

```
iifname @wan ct state { new, untracked } counter name "threats_in" ip saddr @blacklist4 log prefix "CST:threat " limit rate 2/second burst 4 packets drop
```

nftables 里 `limit` 是**匹配表达式**，不是动作。包一旦超出速率就不匹配这条规则的**剩余部分**，于是它既不 `log` 也不 `drop`，直接落到 `policy accept`。

实机对照实验（`burst 1`，连发 20 个包）：

```
规则: tcp dport 22 limit rate 1/minute burst 1 packets drop
      tcp dport 22 counter packets 121 bytes 7121   <== 121 个包穿透了 drop
```

**这不只是统计问题，是安全漏洞：攻击者只要把速率打高就能绕过整个黑名单。**

同时 `counter name` 写在 `ip saddr @blacklist4` **之前**，它统计的是"所有 WAN 入站新连接"而非"被拦截的包"——这解释了为什么 `threats_in` 一直涨（约 4 包/秒）而黑名单命中恒为 0。

修复：拆成两条规则，日志单列、`drop` 无条件，并把方向编码进日志前缀。

### 根因 3【P0】rpcd 缓存旧模块 —— "修好又坏"的机制

ucode 的 `import` 模块在进程内**只加载一次并长期缓存**。升级时用覆盖写替换文件，旧 inode 被 unlink 但 rpcd 仍持有 fd：

```
/proc/11418/fd/44 -> /usr/share/ucode/console/situational.uc (deleted)   fdinfo pos=33088 = 旧版大小
磁盘上的新版      -> 37571 字节
```

实机决定性对照（同一秒、同一份数据库）：

```
ucode 新进程 overview().stats.threat24 = 58
ubus  call                  threat24 = 0      <== 页面看到的
```

包内没有 postinst，`reload_service` 也不重启 rpcd。**所以任何代码修复在部署后都不会在页面上生效。**

修复：部署后必须 `/etc/init.d/rpcd restart`。这条已写进 `init.d` 注释与交付说明（**注意**：不要在 `start_service` 里重启 rpcd，会造成进程竞态、实测出现过多个 rpcd 并存，反而更糟）。

### 根因 4【P1】input 方向的日志被正则整段丢弃

内核日志里 **input 钩子的 `OUT=` 是空值**（`OUT= MAC=...`），只有 forward 才有出接口。旧正则要求 `OUT=\S+`（至少一个非空白字符），于是"外网→路由器"方向的每一条记录都解析失败、被静默丢弃。

实机验证：

```
旧正则  input(OUT=空) : NULL   <== 事件被丢弃
新正则  input(OUT=空) : MATCH  rule=tin src=198.51.100.174
```

修复：`OUT=\S*`，并把正则提取为共用常量，避免两份正则在两个函数里各自漂移。

### 根因 5【P1】dmesg 环形缓冲只有约 129KB / 576 行

```
dmesg | wc -l = 576      dmesg | wc -c = 129274
dmesg -s 1048576 也只多 8 行 -> 环已到顶
每条 CST 约 226B  =>  约 570 条就把环占满
```

`LOG_TAIL = 4000` 是**永远触不到的假保护**（7 倍于整个缓冲）。实证：产生 102 条其他日志后，原有 12 条 `CST:` **全部被挤出**。

修复：
- `LOG_TAIL` 改为 1000（贴合实际容量）
- `kernelEvents()` 改为**同时读 dmesg 与 logread**（logd 的 `-S 1024` = 1MB，保留时间长得多），按 `(stamp,kind,rule,src,dst,dport)` 去重合并

### 根因 6【P2】事件表主键去重过强

主键 `(ts,src,rule,dport)` **不含 `spt`**，同一秒同一来源打到同一端口的多个包会被 `INSERT OR IGNORE` 静默合并。实测 **80 个包只留下 48 行（丢 40%）**，逐秒恰好 1 行。

修复：主键扩展为 `(ts,src,rule,dport,proto,spt,dst)`，并加了**一次性自动迁移**（老库自动重建表、保留历史数据）。

> 迁移判据踩了个坑：ucode 的 `index()` 找不到时返回 **-1 而不是 null**，最初写成 `!= null` 导致条件恒真、迁移永不执行。已修正为 `>= 0` 并实测迁移可正常触发。

### 根因 7【P2】计数器每 6 小时被清零

每次威胁情报刷新都会 `destroy` 整表重建，nft 计数器随之归零，页面"24小时拦截"掉回 0，与数据库口径打架。

修复：重建前把当前读数累加进 `/srv/console-situational/counter-base.json`，页面显示 = 基准 + 当前表内读数。同时去掉了 `inPkts += fwdInPkts` 的重复累加（前端把三方向分列显示，叠加必然虚高）。

### 根因 8【P2】多处静默失败

- `storedEvents()` 的 `catch(e){return []}`：读库失败 = 显示"0 条"，与"真没被攻击"完全无法区分 → 已加 `warn()`
- `collectEvents()` 写库失败仍推进水位 → 这批事件被永久跳过且无日志 → 已改为失败时不推进
- 采集器里威胁任务的空 `catch` → 情报表可连续几天不刷新而页面仍显示"正常" → 已加限流日志

## 运维注意事项

1. **改完这两个 .uc 文件必须重启 rpcd**，否则页面看不到任何变化：
   ```sh
   /etc/init.d/console-security restart
   /etc/init.d/rpcd restart
   ```
2. 部署用**原子替换**，不要原地覆盖：
   ```sh
   cp new.uc /usr/share/ucode/console/.tmp && mv /usr/share/ucode/console/.tmp /usr/share/ucode/console/situational.uc
   ```
3. 任何异常先跑自检，它会直接指出退化项：
   ```sh
   sh /usr/sbin/selftest-situational.sh
   ```
4. **不要在 `console-security` 的 `start_service` 里重启 rpcd** —— 会造成进程竞态（实测出现多个 rpcd 并存、ubus 短暂不可用）。
